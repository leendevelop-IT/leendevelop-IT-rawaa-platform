# رَوَاء | RAWAA

منصة لمراقبة صحة الحدائق والمسطحات الخضراء في جدة من صور القمر الصناعي Sentinel-2. تجمع المنصة القراءات الفضائية الموثقة، وتصنّف حالة كل حديقة، وتتوقع اتجاه الغطاء النباتي، وتجدول المتابعة. وتدير العمل بين الجهة الرقابية والمقاول: تنبيه، ثم مهمة صيانة، ثم صور قبل وبعد، ثم مراجعة أثر التدخل.

هذه النسخة مستقلة ومتكاملة، وجاهزة للرفع إلى مستودع GitHub جديد وللنشر على خدمة Render جديدة.

## 1. ما تحتويه هذه النسخة

النسخة مبنية على مشروع رَوَاء الأصلي (`rawaa-main`). كل صفحاته ووظائفه باقية، وأُضيف إليها ما يلي.

### أ) تطوير الـ Backend والتحليل

| المجال | ما أُضيف |
|---|---|
| بيانات Sentinel-2 L2A | قراءة لكل التقاط فعلي، ثم اختيار أوضح التقاط في كل شهر. تُحفظ مع كل قراءة معرّفات المشاهد (Scene IDs) وعدد البكسلات الصافية ونسبة البكسلات الصالحة، وهذه النسبة لا تعني دقة القراءة |
| السحب والظلال | قناع من طبقة SCL يستبعد الظلال أيضًا (الصنف 2). كل قراءة تُصنَّف: موثوقة (80% فأكثر)، أو محدودة (60–80%)، أو غير موثوقة |
| مصادر البيانات | القراءات الفضائية منفصلة عن المستوردة من CSV واليدوية. المستوردة تُعرض فقط، ولا تدخل في التصنيف أو التنبؤ أو التنبيهات التلقائية |
| حدود الحدائق | تحقق هندسي، ومساحة جيوديسية، واعتماد أو رفض أو تعديل، وسجل إصدارات |
| ملخص القرار | أربع حالات لكل حديقة، مع أسباب مكتوبة: تدخل عاجل، تحتاج متابعة، مستقرة، بيانات غير كافية |
| التنبؤات | NDVI بعد 7 أيام وبعد 30 يومًا، مع نطاقات عدم يقين 80% و95%. النماذج تُختبر على السجل التاريخي (backtesting) وتُقارَن بنموذج بسيط (naive)، ولا يُعرض توقع إذا لم تكفِ البيانات |
| الجدولة والتنبيهات | مواعيد متابعة وتنبيهات تلقائية لا تتكرر عند إعادة التشغيل |
| دورة العمل | تنبيه، ثم مهمة، ثم صور قبل وبعد وملاحظات، ثم مراجعة الجهة الرقابية، ثم مقارنة أثر التدخل وتقييمه |
| الخادم | صلاحيات لكل واجهة API، وترحيلات مرقّمة لقاعدة البيانات، وحدّ لمحاولات الدخول الفاشلة، وسجل طلبات وأخطاء، و`/healthz`، وتقارير CSV، وسجل تدقيق، و44 اختبارًا آليًا |

التفاصيل الفنية في [`docs/BACKEND_INTELLIGENCE.md`](docs/BACKEND_INTELLIGENCE.md).

### ب) إعادة تصميم صفحتين

أُعيد تصميم صفحة تفاصيل الحديقة (ومعها لوحة جانبية بعنوان «عرض التحليل الكامل») وصفحة «التنبؤات وجدولة المتابعة». بقية صفحات المنصة لم تتغير. التفاصيل في [`docs/UI_REDESIGN.md`](docs/UI_REDESIGN.md).

### ج) الجاهزية للنشر

ملف `render.yaml` (Blueprint)، و`.python-version`، و`.env.example`، وسكربتا إدارة الحسابات وتشغيل التحليل في `scripts/`. لا يحتوي المشروع أي مفتاح سري.

> المنصة لا تختلق أي قراءة أو توقع، ولا تشخّص أمراض النباتات أو أعطال الري من صور الأقمار الصناعية وحدها. عندما تظهر إشارة تراجع، توصي بفحص ميداني.

## 3. التشغيل على جهازك

تحتاج Python 3.12. قاعدة البيانات الافتراضية SQLite ولا تحتاج أي إعداد، ويمكن استخدام PostgreSQL بدلًا منها.

```bash
python3.12 -m venv .venv
source .venv/bin/activate            # على Windows:  .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                 # اختياري: الإعدادات المحلية (لا تُرفع إلى GitHub)
uvicorn app:app --reload --port 8000
```

افتح <http://localhost:8000>.

| الحساب | البريد | كلمة المرور |
|---|---|---|
| الجهة الرقابية | `regulator@rawaa.local` | `Rawaa2026!` |
| المقاول | `operator@rawaa.local` | `Rawaa2026!` |

يمكن أيضًا الدخول بزرّي الدخول السريع في صفحة تسجيل الدخول.

- إذا لم تضبط `DATABASE_URL`، تُحفظ البيانات في `data/rawaa.sqlite3`.
- على جهازك اجعل `RAWAA_SECURE_COOKIE=0` (كما في `.env.example`) لأن الاتصال http. لو جعلته `1` فلن يُحفظ كوكي الدخول.
- القاعدة الجديدة تبدأ بثماني حدائق ومواقع تحقق ودون أي قراءة فضائية، لذلك تظهر الحدائق بحالة «بيانات غير كافية» حتى تُجلب قراءات حقيقية من Copernicus (القسم 9).

## 4. الاختبارات الآلية

```bash
pip install -r requirements-dev.txt
pytest                                                     # قاعدة SQLite مؤقتة
RAWAA_TEST_DATABASE_URL=postgresql://user:pass@host/db pytest   # قاعدة PostgreSQL مؤقتة
```

النتيجة المتوقعة: `44 passed`.

> **تحذير:** `RAWAA_TEST_DATABASE_URL` يمسح محتوى المخطط `public` في تلك القاعدة قبل الاختبار. استخدم قاعدة تجريبية فارغة، ولا تستخدم قاعدة الإنتاج أبدًا.

الاختبارات لا تقرأ ملف `.env`، ولا تتصل بالإنترنت؛ اتصالات Copernicus فيها محاكاة.

## 5. رفع المشروع إلى مستودع GitHub جديد

1. أنشئ مستودعًا فارغًا على GitHub، دون README ودون `.gitignore`.
2. فك ضغط الملف، ثم نفّذ داخل المجلد `rawaa-platform`:

```bash
cd rawaa-platform
git init -b main
git add .
git commit -m "RAWAA integrated platform"
git remote add origin https://github.com/<حسابك>/<اسم-المستودع>.git
git push -u origin main
```

قبل الدفع تأكد مما يلي:
- الملفات `app.py` و`render.yaml` و`requirements.txt` يجب أن تكون في جذر المستودع، لا داخل مجلد فرعي. ارفع محتوى المجلد `rawaa-platform`، لا المجلد نفسه.
- إذا رفعت الملفات من واجهة GitHub بالسحب والإفلات، فتأكد أن الملفات المخفية (`.gitignore` و`.python-version` و`.env.example`) رُفعت أيضًا. الرفع بـ `git` أو GitHub Desktop أضمن.
- الملف `.gitignore` يمنع رفع `.env` وقاعدة SQLite المحلية ومجلدات البيئة الافتراضية. **لا ترفع ملف `.env` أبدًا.**

## 6. النشر على Render

يوجد طريقان: Blueprint يُنشئ الخدمة وقاعدة البيانات معًا، أو خدمة ويب يدوية تتصل بقاعدة خارجية مثل Neon، وخطة Neon المجانية لا تنتهي صلاحيتها.

### (أ) Blueprint عبر `render.yaml`

1. في لوحة Render اختر New ثم Blueprint، واربط حساب GitHub، ثم اختر المستودع الجديد.
2. يقرأ Render الملف `render.yaml` ويعرض موردين جديدين:
   - خدمة ويب `rawaa-platform`: Python، الخطة المجانية، منطقة Frankfurt.
   - قاعدة PostgreSQL 16 باسم `rawaa-platform-db`: الخطة المجانية، المنطقة نفسها.

   اخترنا هذين الاسمين ليختلفا عن أي خدمة قائمة اسمها `rawaa`، حتى لا يربطها Render بخدمة موجودة أو يعدّلها. قبل الضغط على Deploy تأكد أن الموردين يظهران كموردين جديدين.
3. سيطلب Render قيمتي `COPERNICUS_CLIENT_ID` و`COPERNICUS_CLIENT_SECRET`. يمكن تركهما فارغين الآن وإضافتهما لاحقًا (القسم 9).
4. اضغط Deploy Blueprint وانتظر انتهاء البناء، ويستغرق عدة دقائق في المرة الأولى.
5. افتح `https://<اسم-الخدمة>.onrender.com/healthz`. يجب أن ترى `"db":"postgres"` و`"schema_version":5`.

بقية الإعدادات مضبوطة في `render.yaml`:

| البند | القيمة |
|---|---|
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app:app --host 0.0.0.0 --port $PORT --proxy-headers` |
| Health Check Path | `/healthz` |
| `DATABASE_URL` | يُربط تلقائيًا بقاعدة `rawaa-platform-db` عبر الشبكة الداخلية |
| `PYTHON_VERSION` | `3.12.7` |
| `RAWAA_SECURE_COOKIE` | `1` |
| `FORWARDED_ALLOW_IPS` | `*` |
| `RAWAA_AUTO_PIPELINE` / `RAWAA_PIPELINE_HOURS` | `1` / `12` |

> **قاعدة Render المجانية تنتهي صلاحيتها بعد 30 يومًا من إنشائها.** بعدها مهلة 14 يومًا للترقية، ثم يحذف Render القاعدة وكل بياناتها. هذه القاعدة بلا نسخ احتياطية، وسعتها 1 GB، ولا يُسمح إلا بقاعدة مجانية واحدة لكل Workspace. قبل انتهاء المدة إما أن ترقّي القاعدة إلى خطة مدفوعة من صفحتها في Render، أو تنقل البيانات إلى PostgreSQL آخر (مثل Neon) وتضع رابطه في `DATABASE_URL` للخدمة.

### (ب) خدمة ويب يدوية مع Neon (أو أي PostgreSQL)

1. أنشئ مشروعًا في [Neon](https://neon.tech)، ويُفضّل اختيار منطقة أوروبية قريبة من Frankfurt. انسخ Connection string، وشكله:
   `postgresql://USER:PASSWORD@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`
2. في Render اختر New ثم Web Service، ثم اختر المستودع واضبط:

| الحقل | القيمة |
|---|---|
| Language | Python 3 |
| Branch | `main` |
| Region | Frankfurt (أو الأقرب لقاعدتك) |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app:app --host 0.0.0.0 --port $PORT --proxy-headers` |
| Instance Type | Free (أو مدفوع) |
| Health Check Path (في Advanced) | `/healthz` |

3. أضف متغيرات البيئة التالية:

```
PYTHON_VERSION=3.12.7
DATABASE_URL=<رابط Neon>
RAWAA_SECURE_COOKIE=1
FORWARDED_ALLOW_IPS=*
RAWAA_AUTO_PIPELINE=1
RAWAA_PIPELINE_HOURS=12
RAWAA_LOG_LEVEL=INFO
COPERNICUS_CLIENT_ID=<اختياري الآن>
COPERNICUS_CLIENT_SECRET=<اختياري الآن>
```

4. اضغط Create Web Service. الجداول تُنشأ تلقائيًا عند أول تشغيل.

خدمة الويب المجانية تتوقف بعد 15 دقيقة بلا زيارات، وقد يستغرق أول طلب بعدها قرابة دقيقة. ملفات القرص على Render مؤقتة وتُمسح عند كل نشر أو إعادة تشغيل، ولهذا يلزم `DATABASE_URL`: كل البيانات، بما فيها صور المهام، محفوظة في قاعدة البيانات.

## 7. متغيرات البيئة

| المتغير | إلزامي؟ | القيمة المقترحة على Render | الوظيفة |
|---|---|---|---|
| `DATABASE_URL` | نعم، لحفظ البيانات | من قاعدة Render أو رابط Neon | PostgreSQL. بدونه تُستخدم SQLite على القرص المؤقت فتضيع البيانات |
| `RAWAA_SECURE_COOKIE` | نعم، على HTTPS | `1` | كوكي الجلسة لا يُرسل إلا عبر https (محليًا: `0`) |
| `PYTHON_VERSION` | مستحسن | `3.12.7` | الإصدار المختبر |
| `FORWARDED_ALLOW_IPS` | مستحسن | `*` | مع `--proxy-headers` يقرأ الخادم عنوان الزائر الحقيقي وبروتوكول https من وكيل Render |
| `COPERNICUS_CLIENT_ID` | لا، لكنه لازم للبيانات الفعلية | قيمة سرية | عميل OAuth من Copernicus Data Space |
| `COPERNICUS_CLIENT_SECRET` | لا، لكنه لازم للبيانات الفعلية | قيمة سرية | السر المرافق للعميل |
| `RAWAA_AUTO_PIPELINE` | لا | `1` | تشغيل التحليل والجدولة تلقائيًا داخل الخادم |
| `RAWAA_PIPELINE_HOURS` | لا | `12` | عدد الساعات بين التشغيلات التلقائية |
| `RAWAA_LOG_LEVEL` | لا | `INFO` | مستوى السجلات: `DEBUG` أو `INFO` أو `WARNING` |
| `RAWAA_ENV` | لا | `production` عند الاستخدام الفعلي | يعطّل مبدّل الأدوار التجريبي |
| `RAWAA_DEMO_SWITCH` | لا | `0` | يعطّل مبدّل الأدوار فقط (بديل لـ `RAWAA_ENV`) |
| `RAWAA_TILE_CACHE` | لا | (الافتراضي `/tmp/rawaa-tiles`) | تخزين مؤقت لبلاطات صور Sentinel-2 |
| `RAWAA_DB` | محليًا فقط | — | مسار ملف SQLite عند غياب `DATABASE_URL` |

متغيرات الاختبارات (لا تُضبط على Render): `RAWAA_TEST_DATABASE_URL` و`RAWAA_KEEP_DEMO` و`RAWAA_NO_DOTENV`.

القيم السرية توضع في Render في صفحة الخدمة ضمن Environment فقط، وعلى جهازك في `.env`، ولا توضع في `render.yaml` ولا في أي ملف يُرفع إلى GitHub.

## 8. الوظائف التي تحتاج مفاتيح API أو خدمات خارجية

المفتاح السري الوحيد الذي يحتاجه المشروع هو عميل OAuth من Copernicus، إضافة إلى رابط قاعدة البيانات. بقية الوظائف تعمل دون مفاتيح.

| الوظيفة | ما تحتاجه | ماذا يحدث بدونه |
|---|---|---|
| جلب القراءات الفضائية (زر «جلب قراءات فضائية» في صفحة الحديقة): مؤشرات NDVI وNDMI وNDRE وSAVI وNDWI من Sentinel-2، مع معرّفات المشاهد ونسبة البكسلات الصالحة | `COPERNICUS_CLIENT_ID` و`COPERNICUS_CLIENT_SECRET` | تظهر رسالة بأن Copernicus غير مربوط، وتنتقل الواجهة إلى الإعدادات، ولا تُنشأ أي قراءة |
| طبقات صور Sentinel-2 على الخريطة (ألوان حقيقية، NDVI، الرطوبة…) وصورة الحديقة | مفتاحا Copernicus | تظهر الخريطة الأساسية فقط |
| حرارة السطح من Landsat 8/9 (أثر التبريد) | مفتاحا Copernicus (العميل نفسه) | لا قراءات حرارية، والقراءات النباتية لا تتأثر |
| التصنيف والتنبؤ والجدولة والتنبيهات التلقائية | لا مفاتيح، لكنها تحتاج قراءات فضائية موثوقة: 4 على الأقل للتصنيف و6 على الأقل للتنبؤ | الحالة «بيانات غير كافية»، ولا يُعرض توقع |
| الخريطة الأساسية (صور Esri World Imagery) | لا مفتاح. يجلبها متصفح المستخدم من `server.arcgisonline.com` | — |
| الخطوط (Google Fonts) والأيقونات (lucide عبر unpkg) | لا مفتاح. تُحمَّل في متصفح المستخدم | إذا حُجبت يعمل الموقع بخط بديل ودون أيقونات |
| حدود الحدائق | مضمّنة في الكود (مصدرها OpenStreetMap)، ولا تحتاج اتصالًا خارجيًا | — |
| حفظ البيانات | `DATABASE_URL` | تضيع البيانات عند كل نشر أو إعادة تشغيل |
| استيراد CSV، والمهام، وصور قبل/بعد، والتقارير، والسجل، وإدارة الحدود | لا شيء خارجي | — |

## 9. ربط Copernicus (بيانات الأقمار الصناعية الفعلية)

1. أنشئ حسابًا مجانيًا في [Copernicus Data Space Ecosystem](https://dataspace.copernicus.eu).
2. افتح لوحة Sentinel Hub على <https://shapps.dataspace.copernicus.eu/dashboard/#/account/settings> (صفحة User settings).
3. في قسم OAuth clients اضغط Create، واكتب اسمًا مثل `rawaa-render`. إذا طُلب نوع التدفق فاختر Client Credentials.
4. انسخ Client ID وClient secret فورًا، **لأن السر لا يظهر إلا مرة واحدة**.
5. في Render افتح الخدمة، ثم Environment، وضع القيمتين في `COPERNICUS_CLIENT_ID` و`COPERNICUS_CLIENT_SECRET`، ثم Save and deploy.
6. للتحقق: يجب أن يُظهر `/healthz` القيمة `"copernicus_configured": true`. افتح بعدها حديقة في المنصة واضغط «جلب قراءات فضائية». الزر يجلب آخر 3 سنوات ويعرض عدد القراءات المحفوظة، ثم يُعاد التحليل تلقائيًا (القرار والتنبؤ والجدولة).

ملاحظات:
- الحساب المجاني في Copernicus له حصص استخدام. راجع صفحة Quotas and Limitations في توثيق Copernicus، ولا تكرر الجلب لنفس الحديقة دون حاجة.
- المنصة تستخدم مسارات CDSE الحالية: `/statistics/v1` و`/catalog/v1/search` و`/process/v1`.
- إذا ظهر الخطأ `Copernicus HTTP 401`، فالسر خاطئ أو العميل محذوف. أنشئ عميلًا جديدًا وحدّث المتغيرين.

## 10. الحسابات والأمان

كلمة مرور الحسابات التجريبية (`Rawaa2026!`) معروضة في صفحة الدخول ومعها زرّا دخول سريع، كما في المنصة الأصلية. هذا يناسب عرضًا تجريبيًا، **ولا يناسب بيانات حقيقية**.

قبل الاستخدام الفعلي:
1. أضف `RAWAA_ENV=production` في Environment. هذا يعطّل مبدّل الأدوار الذي يسمح لحساب تجريبي بالتبديل بين «جهة رقابية» و«مقاول» دون كلمة مرور.
2. غيّر كلمات المرور أو أنشئ حسابات حقيقية بالسكربت `scripts/manage_users.py`:

```bash
python scripts/manage_users.py list
python scripts/manage_users.py set-password regulator@rawaa.local 'كلمة-مرور-قوية-جديدة'
python scripts/manage_users.py create inspector@example.org "اسم يظهر في المنصة" regulator 'كلمة-مرور-قوية'
python scripts/manage_users.py create contractor@example.org "شركة الصيانة" operator 'كلمة-مرور-قوية'
python scripts/manage_users.py assign-areas contractor@example.org all     # أو أرقام الحدائق: 3,5,8
```

- الأدوار: `regulator` للجهة الرقابية و`operator` للمقاول. كلمة المرور 10 أحرف على الأقل.
- تغيير كلمة المرور يُخرج المستخدم من كل جلساته.
- بعد تغيير كلمات مرور الحسابات التجريبية يتوقف زرّا الدخول السريع عن العمل، وهذا متوقع.

السكربت يستخدم `DATABASE_URL` نفسه الذي يستخدمه الموقع، ومكان تشغيله يتوقف على خطة الخدمة:
- خدمة Render مدفوعة: من تبويب Shell في صفحة الخدمة.
- خدمة Render مجانية: الخطة المجانية لا تتيح Shell، فشغّله من جهازك بعد تثبيت المتطلبات.
  - مع قاعدة Render: الملف `render.yaml` يمنع الاتصال بالقاعدة من الإنترنت (`ipAllowList: []`). أضف عنوان IP جهازك مؤقتًا من إعدادات الوصول في صفحة القاعدة على Render (Networking / Access Control)، ثم انسخ External Database URL ونفّذ:
    `DATABASE_URL="<External Database URL>" python scripts/manage_users.py list`
    احذف عنوانك بعد الانتهاء. مزامنة الـ Blueprint تعيد القائمة فارغة على أي حال.
  - مع Neon: استخدم رابط Neon مباشرة بالطريقة نفسها.

الحمايات المفعّلة:
- كلمات المرور مخزنة بتجزئة PBKDF2-SHA256.
- كوكي الجلسة `httpOnly` لمدة 24 ساعة.
- بعد 8 محاولات دخول فاشلة لنفس البريد خلال 15 دقيقة يُرفض الدخول مؤقتًا (رمز 429).
- كل واجهة API محمية بالدور المناسب.
- المقاول لا يرى إلا الحدائق المسندة إليه.

## 11. التحليل التلقائي والجدولة

- مع `RAWAA_AUTO_PIPELINE=1` يبدأ التحليل بعد 60 ثانية من تشغيل الخادم، ثم يتكرر كل `RAWAA_PIPELINE_HOURS` ساعة. كل تشغيل يحسب القرار والتنبؤ ومواعيد المتابعة والتنبيهات التلقائية.
- إعادة التشغيل أو تكرار الأمر لا تُنشئ تنبيهات أو مواعيد أو توقعات مكررة، وقد اختُبر ذلك. كل تشغيل يُسجَّل، ويظهر آخر تشغيل في صفحة «التنبؤات وجدولة المتابعة».
- يمكن تشغيله يدويًا من زر «تشغيل التحليل الآن» في الصفحة نفسها، ويعمل تلقائيًا أيضًا بعد كل «جلب قراءات فضائية».
- على الخطة المجانية لا يعمل التحليل التلقائي إلا والخدمة مستيقظة، ويعمل أيضًا بعد 60 ثانية من كل استيقاظ. لجدولة مضمونة التوقيت أنشئ Cron Job في Render (ميزة مدفوعة):
  - الأمر: `python scripts/run_pipeline.py`
  - Build Command: `pip install -r requirements.txt`
  - ضع فيه `DATABASE_URL` نفسه الخاص بالخدمة.
- التحليل التلقائي يعمل على القراءات المخزنة ولا يجلب قراءات جديدة من Copernicus. الجلب يتم بزر «جلب قراءات فضائية» لكل حديقة، كما في المنصة الأصلية.

## 12. التحقق بعد النشر

1. `https://<الخدمة>.onrender.com/healthz` يجب أن يعيد:
   `{"ok":true,"db":"postgres","schema_version":5,"copernicus_configured":…}`
2. ادخل بحساب الجهة الرقابية. تظهر لوحة التحكم، وتعمل كل عناصر القائمة الجانبية.
3. في «مناطق التشجير» افتح حديقة، واضغط «اعتماد الحدود» في بطاقة الحدود للحدائق ذات مضلعات OSM.
4. في «التنبؤات وجدولة المتابعة» اضغط «تشغيل التحليل الآن». إذا لم توجد قراءات فستظهر كل الحدائق «بيانات غير كافية»، وهذا السلوك الصحيح.
5. بعد ربط Copernicus اجلب القراءات لحديقة، وراجع سجل القراءات (التاريخ، معرّف المشهد، نسبة البكسلات الصالحة)، ثم شغّل التحليل.
6. جرّب دورة العمل كاملة: تنبيه، ثم «إسناد»، ثم التبديل إلى المقاول، ثم «بدء» ورفع صورتي قبل وبعد ثم «إنجاز»، ثم العودة إلى الجهة الرقابية و«اعتماد» المهمة.
7. في «التقارير» نزّل ملفات CSV: المهام، وبيانات التدريب، والقرارات، والجدولة، والتوقعات، وسجل التدقيق.

## 13. حل المشكلات الشائعة

| العَرَض | السبب والحل |
|---|---|
| فشل البناء على Render بسبب إصدار Python | تأكد من `PYTHON_VERSION=3.12.7` ومن وجود `.python-version` في جذر المستودع |
| `/healthz` يُظهر `"db":"sqlite"` | `DATABASE_URL` غير مضبوط والبيانات ستضيع. اضبطه ثم أعد النشر |
| فشل التشغيل وفي السجل خطأ اتصال بـ PostgreSQL | الرابط خاطئ، أو القاعدة في منطقة أخرى مع استخدام الرابط الداخلي، أو انتهت مدة قاعدة Render المجانية |
| الدخول يعيدك إلى صفحة الدخول | على جهازك (http) اجعل `RAWAA_SECURE_COOKIE=0`، وعلى Render (https) اجعله `1` |
| رسالة «محاولات كثيرة» (429) | انتظر 15 دقيقة، أو غيّر كلمة المرور بالسكربت |
| «Copernicus not connected» | المفتاحان غير مضبوطين (القسم 9) |
| `Copernicus HTTP 401` | المعرّف أو السر خاطئ، أو العميل محذوف. أنشئ عميلًا جديدًا |
| `Copernicus HTTP 403` أو `429` | تجاوزت حصة الاستخدام أو حد الطلبات. انتظر ثم أعد المحاولة |
| الصفحة تستغرق دقيقة لتفتح | الخدمة المجانية تستيقظ بعد توقف |
| اختفت البيانات بعد شهر | انتهت مدة قاعدة Render المجانية (القسم 6). رقِّ القاعدة أو انقل البيانات |
| الخريطة الأساسية لا تظهر | الشبكة تحجب `server.arcgisonline.com`. طبقات Sentinel تحتاج مفاتيح Copernicus |

السجلات في Render تحت Service ثم Logs. كل طلب يحمل معرّفًا (`X-Request-ID`) يظهر أيضًا في رسالة أي خطأ داخلي.

## 14. القيود المعروفة

- لا تشخّص المنصة الأمراض أو أعطال الري من الأقمار الصناعية وحدها؛ تُظهر التغير وتوصي بفحص ميداني، ويُسجَّل السبب الفعلي عند إنجاز المهمة.
- ثلاث حدائق حدودها تقريبية (مستطيل حول موقع الحديقة): الهدى، وأبرق الرغامة، وموقع التحقق ٢. يجب رسم حدودها الصحيحة واعتمادها قبل الاعتماد على قراءاتها.
- التصنيف يحتاج 4 قراءات فضائية موثوقة على الأقل، والتنبؤ يحتاج 6، وقبل ذلك تظهر «بيانات غير كافية».
- القراءات المستوردة من CSV تُعرض كبيانات غير موثّقة ولا تؤثر على القرار.
- الخطة المجانية في Render: توقف بعد 15 دقيقة بلا زيارات، وصلاحية القاعدة 30 يومًا، ولا نسخ احتياطية.
- الواجهة تحمّل الخطوط والأيقونات وصور الخريطة الأساسية من الإنترنت في متصفح المستخدم.
